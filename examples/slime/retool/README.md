# SLIME ReTool Moonlight RL

This is a repo-owned Moonlight-16B-A3B ReTool RL example for the pinned SLIME
sidecar. It runs a local Python tool loop through SLIME custom generation and a
custom reward hook:

```text
JSONL prompts -> SGLang rollout -> generate_with_retool.generate
  -> local code_interpreter tool -> generate_with_retool.reward_func
  -> GRPO/Megatron train step -> checkpoint -> W&B
```

The task layer has no E2B, no external browser sandbox, and no hosted tool
service. The only tool exposed to the model is the local `code_interpreter`
implemented in `tool_sandbox.py`.

## What This Patch Claims

This patch claims infra readiness, not model improvement.

The runtime profile this launcher encodes was validated from this repo branch:

- model: `Moonlight-16B-A3B-Instruct`
- precision path: BF16 HF weights plus converted Megatron `torch_dist`
- task: repo-owned 16-row AIME-style math JSONL with local Python tool use
- hardware used for validation: four visible H200 GPUs from an 8x H200 Lium pod
- max sampled VRAM: `71863 MiB` per GPU
- W&B run: `https://wandb.ai/ahm-rimer/slime-retool-moonlight/runs/elccxpwb`
- result: Ray job terminal status `SUCCEEDED`, wrapper status `0`, checkpoint
  saved at `iter_0000001`

The same 80 GB memory profile is intended for 4x A100 80 GB, but this patch does
not claim a completed A100 run. H200 is not a substitute for exact A100
architecture validation; the useful claim is that the measured peak was below an
80 GB per-GPU budget on a real four-GPU SLIME/Megatron/SGLang run. This patch
also does not claim learning improvement: the validated run used one train step,
`n_samples_per_prompt=1`, short responses, and eval disabled.

The command in the AIME section below is written to reproduce the validated
profile from this repo path, with actor load defaulting to `SLIME_REF_LOAD_DIR`
and checkpoints saved under
`.w8-biayn/slime/retool/moonlight-rl/checkpoints/<run-id>/`.

## Files

- `retool_moonlight_rl.sh`: Moonlight SLIME GRPO launcher.
- `generate_with_retool.py`: custom generation function and custom reward hook.
- `tool_sandbox.py`: local Python tool registry and sandbox.
- `moonlight_math_tool_smoke.jsonl`: tiny local smoke dataset.
- `moonlight_math_tool_aime_style.jsonl`: 16-row local reproduction dataset.
- `requirements.txt`: Python packages needed by the ReTool task hook.

## Prerequisites

Run these steps inside a GPU node/container where SLIME and Megatron are
available.

1. Clone this repo and enter it.

   ```bash
   cd /workspace/browser-is-all-you-need
   ```

2. Refresh the pinned SLIME sidecar if it is not already present.

   ```bash
   uv run w8-biayn upstreams clone slime
   ```

3. Start the SLIME container generated by the repo tooling. The launcher must run
   where `ray`, `python3`, `nvidia-smi`, SLIME, and Megatron are on `PATH`.

   ```bash
   .w8-biayn/slime/run-container.sh
   ```

   The generated launcher keeps the stack ulimit on by default and leaves
   `memlock=-1` off for managed hosts that reject that rlimit before container
   startup. If your host allows it, opt in with:

   ```bash
   SLIME_DOCKER_MEMLOCK_ULIMIT=1 .w8-biayn/slime/run-container.sh
   ```

   The launcher raises the in-container open-file soft limit to
   `SLIME_NOFILE_SOFT_LIMIT=65536` before Ray starts. Keep that default unless
   the host already provides a higher soft `nofile` limit.

4. Install the local ReTool hook dependencies inside the container. This also
   installs `huggingface-hub`, which the launcher uses for first-run model
   download.

   ```bash
   pip install -r examples/slime/retool/requirements.txt
   ```

5. Run the launcher. If the model is not present, the launcher downloads
   `moonshotai/Moonlight-16B-A3B-Instruct` to:

   ```text
   /root/models/Moonlight-16B-A3B-Instruct
   ```

   If the converted Megatron checkpoint is not present, the launcher then
   converts the HF checkpoint to:

   ```text
   /root/models/Moonlight-16B-A3B-Instruct_torch_dist
   ```

   Override these defaults when needed:

   ```bash
   export SLIME_HF_MODEL_ID=moonshotai/Moonlight-16B-A3B-Instruct
   export SLIME_HF_CHECKPOINT=/path/to/Moonlight-16B-A3B-Instruct
   export SLIME_REF_LOAD_DIR=/path/to/Moonlight-16B-A3B-Instruct_torch_dist
   ```

   By default the actor starts from `SLIME_REF_LOAD_DIR`. To resume from a prior
   trained checkpoint instead, set `SLIME_ACTOR_LOAD_DIR`.

   Set `SLIME_DOWNLOAD_HF_CHECKPOINT=0` only for offline/manual setups where
   `SLIME_HF_CHECKPOINT` already points at a complete local HF checkpoint.

   ```bash
   SLIME_DOWNLOAD_HF_CHECKPOINT=0 \
   SLIME_HF_CHECKPOINT=/path/to/Moonlight-16B-A3B-Instruct \
   bash examples/slime/retool/retool_moonlight_rl.sh
   ```

## Tiny Local Smoke

Use this command first. It uses the four-row local JSONL and disables eval, so it
only checks that the Moonlight ReTool training loop starts, rolls out, trains,
writes a checkpoint, and exits.

```bash
cd /workspace/browser-is-all-you-need

SLIME_NUM_GPUS=4 \
SLIME_NUM_ROLLOUT=1 \
SLIME_ROLLOUT_BATCH_SIZE=4 \
SLIME_N_SAMPLES_PER_PROMPT=1 \
SLIME_GLOBAL_BATCH_SIZE=4 \
SLIME_MAX_RESPONSE_LEN=256 \
SLIME_MAX_TOKENS_PER_GPU=4096 \
SLIME_ROLLOUT_NUM_GPUS_PER_ENGINE=4 \
SLIME_SGLANG_MEM_FRACTION=0.45 \
SLIME_SGLANG_CUDA_GRAPH_MAX_BS=16 \
SLIME_SGLANG_DISABLE_CUSTOM_ALL_REDUCE=1 \
SLIME_OPTIMIZER_CPU_OFFLOAD=1 \
SLIME_TRAIN_MEMORY_MARGIN_BYTES=268435456 \
SLIME_CONVERT_NPROC=4 \
SLIME_DISABLE_EVAL=1 \
SLIME_SAVE_INTERVAL=1000 \

```

Expected local artifacts:

- `.w8-biayn/slime/retool/moonlight-rl/runs/<timestamp>/run.log`
- `.w8-biayn/slime/retool/moonlight-rl/runs/<timestamp>/vram_usage.csv`
- `.w8-biayn/slime/retool/moonlight-rl/runs/<timestamp>/vram_peak.txt`
- `.w8-biayn/slime/retool/moonlight-rl/runs/<timestamp>/run_receipt.txt`

The run passes when `run_receipt.txt` contains `status=0` and
`ray_job_terminal_status=SUCCEEDED`.

## AIME 4-GPU Reproduction Profile

The 4-GPU profile uses the repo-owned 16-row AIME-style JSONL:

```text
examples/slime/retool/moonlight_math_tool_aime_style.jsonl
```

Each row contains a `prompt` and integer `label`, so no external dataset
download is needed for reproduction. Replace `SLIME_PROMPT_DATA` only when you
want to run a different task file. The launcher resolves this repo-relative path
to an absolute path before submitting the Ray job, because the Ray entrypoint
runs from the SLIME checkout.

The profile below intentionally uses batch size `4` to keep host-RAM pressure
low on 4x80 GB machines. Increase `SLIME_ROLLOUT_BATCH_SIZE` and
`SLIME_GLOBAL_BATCH_SIZE` only after this conservative run succeeds.

```bash
cd /workspace/browser-is-all-you-need

SLIME_PROMPT_DATA=examples/slime/retool/moonlight_math_tool_aime_style.jsonl \
SLIME_NUM_GPUS=4 \
SLIME_NUM_ROLLOUT=1 \
SLIME_ROLLOUT_BATCH_SIZE=4 \
SLIME_N_SAMPLES_PER_PROMPT=1 \
SLIME_GLOBAL_BATCH_SIZE=4 \
SLIME_MAX_RESPONSE_LEN=256 \
SLIME_MAX_TOKENS_PER_GPU=4096 \
SLIME_ROLLOUT_NUM_GPUS_PER_ENGINE=4 \
SLIME_SGLANG_MEM_FRACTION=0.45 \
SLIME_SGLANG_CUDA_GRAPH_MAX_BS=16 \
SLIME_SGLANG_DISABLE_CUSTOM_ALL_REDUCE=1 \
SLIME_OPTIMIZER_CPU_OFFLOAD=1 \
SLIME_TRAIN_MEMORY_MARGIN_BYTES=268435456 \
SLIME_CONVERT_NPROC=4 \
SLIME_DISABLE_EVAL=1 \
SLIME_SAVE_INTERVAL=1000 \
SLIME_WANDB_PROJECT=slime-retool-moonlight \
SLIME_WANDB_GROUP=aime-style-4gpu-smoke \
SLIME_WANDB_RUN_ID=moonlight-retool-aime-style-4gpu-$(date -u +%Y%m%d%H%M%S) \
bash examples/slime/retool/retool_moonlight_rl.sh
```

The launcher defaults to `--no-save-optim --no-save-rng` to keep the smoke
checkpoint small. Set `SLIME_SAVE_OPTIM_RNG=1` only when optimizer and RNG state
are required.

## W&B

The launcher enables W&B when any of these is true:

- `WANDB_API_KEY` or `WANDB_KEY` is set;
- `wandb login` has already created `${HOME}/.netrc`;
- `wandb` settings exist at `${HOME}/.config/wandb/settings`;
- `SLIME_WANDB_PROJECT` is set.

Useful metric groups from the validated run:

- `train/*`: loss, policy-gradient loss, entropy loss, KL loss, grad norm,
  learning rate, global batch size, train step.
- `rollout/*`: reward, raw reward, KL, advantages, returns, response length,
  truncation, prefix-cache hit rate.
- `perf/*`: rollout time, train time, step time, train wait time, actor train
  tokens/sec, rollout tokens/sec/GPU.
- `debug/*`: available tools, tools used, payload length, ReTool turn.

This patch does not add rich W&B rollout tables. Prompt/completion/failure
tables are future observability work.

## Common Failures

`Missing HF checkpoint`

The launcher downloads `SLIME_HF_MODEL_ID` to `SLIME_HF_CHECKPOINT` by default.
If this appears, `SLIME_DOWNLOAD_HF_CHECKPOINT=0` was set or the download failed
before writing a valid `config.json`. Check network access and, for private or
rate-limited Hugging Face environments, authenticate with `huggingface-cli login`
or `HF_TOKEN`.

`Missing Megatron torch_dist checkpoint`

The HF checkpoint has not been converted for Megatron and
`SLIME_CONVERT_IF_MISSING=0` was set. Either unset it, set
`SLIME_REF_LOAD_DIR` to an existing converted checkpoint, or run once with:

```bash
SLIME_CONVERT_IF_MISSING=1 SLIME_CONVERT_NPROC=4 \
bash examples/slime/retool/retool_moonlight_rl.sh
```

`The SLIME runtime is not active: 'ray' is missing from PATH.`

You are outside the SLIME container or the SLIME environment is not sourced.
Start the generated SLIME container before running the launcher.

`No dot product attention backend is available`

Rerun with Transformer Engine diagnostics:

```bash
NVTE_DEBUG=1 \
NVTE_DEBUG_LEVEL=2 \
NVTE_FLASH_ATTN=1 \
NVTE_FUSED_ATTN=1 \
NVTE_ALLOW_NONDETERMINISTIC_ALGO=1 \
bash examples/slime/retool/retool_moonlight_rl.sh
```

`run_receipt.txt` has nonzero `status` or no terminal Ray success

Open `run.log` first, then check `vram_peak.txt`. The most useful first split is
whether failure happened before Ray job submission, during SGLang startup, during
rollout generation, during train step, or during checkpoint save.
